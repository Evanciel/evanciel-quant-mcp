### 순서 1 — P1-6 일일손실 한도 통화 분리 (low, 즉시)

의존성: 없음. 가장 독립적·저위험. 먼저 처리해 사이클을 빠르게 닫는다.

**변경 파일**: `src/brokers/safety.ts`, `.env.example`, `SETUP-LIVE.md`, `test/safety.test.ts`
(runner.ts는 미변경 — fillOrder가 broker 기반으로 quoteCurrency를 이미 명시하므로 자동 정합)

**핵심 단계**:
1. `dailyRealizedLoss(quoteCurrency?: string)` 오버로드 — `bots` 조인으로 broker→통화 추론(Binance=USDT, KIS/키움=KRW). 인자 미지정 시 전체(이전 호환).
2. `checkLimits()` 읽기 우선순위 **명확히**: ① 분리 명시값(`LIVE_DAILY_LOSS_LIMIT_USDT`/`_KRW`) → ② 하위호환 단일값(`LIVE_DAILY_LOSS_LIMIT`) → ③ `LIVE_DEFAULTS_BY_CCY[ccy].dailyLoss` 기본값.
3. quoteCurrency 불명(null) 시 `DEFAULT_CCY=USDT` 적용(실경로에선 발생 안 함 — fail-closed 무해화).
4. `.env.example`: `_USDT`(달러, 기본50) / `_KRW`(원, 기본75000) 주석. 단일값은 `(하위호환)` 표기.
5. `SETUP-LIVE.md`: 통화별 가이드 + 단일값→분리값 **마이그레이션 섹션**(미설정 시 기본값으로 자동 무해화 명시).

**테스트**: 통화별 dailyRealizedLoss 분리 조회(KRW봇10+USDT봇10), checkLimits 독립 서킷(KRW -75000 도달 시 USDT 무영향, 역도), 하위호환(분리 미설정→기본값), KST 경계 재확인.

**적대검증 필수 반영**: 오버로드 JOIN 필수 / env 우선순위 순서 주석 명시 / 마이그레이션 섹션 필수 / bots 조인 성능은 인덱스 활용.

**패리티 보존**: dailyRealizedLoss는 read-only 순수함수, 서킷은 라이브 전용 → backtest 0영향.

### 순서 2 — P1-24 감사로그 실패 운영 정책 (medium)

의존성: P1-6과 같은 safety.ts를 만지므로 연속 처리(머지 충돌 최소화). fail-closed 교정 포함.

**변경 파일**: `src/brokers/safety.ts`, `src/mcp-server/live-handlers.ts`, `src/mcp-server/index.ts`, `src/dashboard/server.ts`, `SECURITY.md`, `SETUP-LIVE.md`, `test/safety.test.ts`

**핵심 단계**:
1. **fail-closed 교정(최우선)**: `dailyRealizedLoss()` catch를 `return 0`(fail-open) → `return Number.POSITIVE_INFINITY`(서킷 트리거)로 변경. stderr 경고 '일일손실 조회 실패 → 서킷 안전 폴백'. ※ 이 변경은 P1-6 오버로드와 동일 함수이므로 P1-6 직후 같이 반영.
2. `AUDIT_FAILURE_HALT` env(opt-in, 기본 false) + 임계값(기본 10회). `liveGate()`에 통합: `if (AUDIT_FAILURE_HALT==='true' && auditFailureCount() > N) return {allowed:false, reason:'감사로그 누적 실패 → 주문 차단'}`.
3. `auditFailureCount()`/`lastAuditError()` 노출 → `liveStatus()`에 `auditStatus:{failures,lastError,haltEnforced}` 필드.
4. 대시보드 `/api/audit-health`(쿠키 검증 권장) — `{ok,failures,lastError,timestamp}`. 위젯: failures>0 시 경고.
5. `SECURITY.md`: '## Audit Log Integrity' 절(append-only, disk-failure, stderr alerts, 쿠키 포트 비스코프).
6. `SETUP-LIVE.md`: '## 감사무결성 모니터링' 절(점검법, 대응, AUDIT_FAILURE_HALT 옵션, 임계값 10 가이드, LIVE_TRADING_HALT와 구분).

**테스트**: AUDIT_FAILURE_HALT threshold(0 즉시차단 / 3회통과·4회차단 / 미설정 회귀), `dailyRealizedLoss` DB throw → POSITIVE_INFINITY → checkLimits 서킷 발화.

**적대검증 필수 반영**: catch fail-open→fail-closed 전환(대칭성 회복) / HALT 기본 false 강제(가용성 보호) / liveGate 통합 / 문서 신설 필수.

**패리티 보존**: audit는 backtest 미호출 → 0영향. HALT opt-in=false → 기존 흐름 불변.

### 순서 3 — P1-22 캔들 재시도/간극 감지 (medium)

의존성: 없음(데이터 레이어). 신호 품질 게이트라 reconcile 항목들보다 먼저 깔아두면 안전망 확대.

**변경 파일**: `src/data/binance-public.ts`, `src/runner/runner.ts`, `src/brokers/base.ts`, `src/brokers/kiwoom.ts`, `src/brokers/kis.ts`, (+ 신규 `src/util/candle.ts`)

**핵심 단계**:
1. **[필수]** `fetchKlines` + `Kiwoom.getCandles` 양쪽 `withRetry` 감싸기 `{attempts:3, baseDelayMs:400, maxDelayMs:8000}`. 타임아웃/429/5xx만 재시도(4xx 비재시도). 실패 로깅 필수.
2. **[필수]** `validateCandleContiguity(bars, interval) → {isValid, gaps?}` 신규(util/candle.ts). 간극 시 경보 로그 + **데이터 버림(반환 [])** (보수적).
3. **[필수]** KR interval 검증: tickBot에서 getCandles 응답 interval vs 요청 interval(secsToInterval) strict 비교. 불일치 throw. (Kiwoom 반환에 interval 필드 추가 또는 요청값 캐시 비교.)
4. **[필수]** KIS `getCandles` **fail-closed**: `throw new Error('KIS 캔들 API 미지원 — 현재 Binance 공개 데이터만 사용 가능')`. 조용한 빈배열 hold 금지.
5. **[권고]** tickBot 게이트: `data.length<30` 외 contiguity !isValid도 동일 hold. 간극 상세 로깅.
6. **[권고]** `CANDLE_GAP_TOLERANCE_BARS`(기본 0=엄격) env. 지금은 strict 고정 권장.

**테스트**: 네트워크 실패→withRetry 백오프, 봉 누락 배열→경보+hold, KR interval 미스매치→거절, KIS getCandles→미지원 throw, data<30 hold, 재시도 후 부분데이터→간극 유지 hold.

**적대검증 필수 반영**: withRetry는 fetchKlines+Kiwoom 둘 다(한쪽만 = 누락) / KIS는 '미구현 명시'가 아니라 throw(fail-closed) / contiguity 함수 실제 구현(현재 0건) / interval strict 비교.

**패리티 보존**: backtest·live 동일 fetch+검증 경로 사용. 간극 시 양쪽 모두 hold(신호 없음) → 동일 동작.

### 순서 4 — P1-2 unknown 누적 → 강제 reconcile (medium, 설계결정 선행)

의존성: P1-22(데이터 안전망) 이후. **코딩 전 §3 설계결정 Q1·Q2·Q4 확정 필수.** base.ts 백오프는 P1-22에서 추가된 것을 재사용/확장.

**변경 파일**: `src/runner/runner.ts`, `src/core/execution/reconcile.ts`, `src/brokers/base.ts`, `docs/.../mainnet-pilot-runbook.md`

**핵심 단계**:
1. `PaperPosition`에 `unknownCount:number`(기본0) 추가. DB는 position_state TEXT(JSON)라 스키마 변경 없음.
2. fillOrder verdict='unknown' 시 `unknownCount++` + audit `fill_unknown_accumulated`. (심볼 독립 추적 — 단일봇 전용.)
3. tickBot: reconcileLivePosition 직후·신호평가 전 `if ((cur?.unknownCount??0) >= UNKNOWN_MAX_COUNT) { 강제 reconcile + audit 'fill_unknown_reconcile_triggered' }`. 재귀 회피.
4. 리셋 정책 **명시**: reconcile 성공(adopt/no_exchange_pos/in_sync) → `unknownCount:0`. reconcile 실패(throw) → **유지**(다음 틱 재시도) + audit `fill_unknown_reconcile_failed`.
5. `UNKNOWN_MAX_COUNT` env화: `LIVE_UNKNOWN_MAX_COUNT` clamp 1~20, 기본5 (PROTECTIVE_MAX_FAILS 패턴).
6. **429 백오프**: base.ts `withBackoff(fn,{isRetryable:e=>e?.code===429||/429/.test(e?.message)})`로 getOrderByClientId/getPositions wrap. 폭주 방지.
7. **스캐너 제외**: tickBot 상단 술어 — 스캐너/멀티심볼이면 'unknown reconcile 미적용(단일봇 전용)' 로그 후 return.
8. runbook: KR 최악 손절 공백(=interval×MAX_COUNT) 명시, testnet vs 메인넷 차이, 백오프 전략.

**테스트**: unknown 3~5틱 누적, 임계 도달→reconcile 호출, 성공 후 리셋, 심볼 독립성, 실패시 유지, Binance(지원)→unknown 경로 미진입(회귀0), KR→누적·트리거, 429 백오프, reconMisses/protFails 독립.

**적대검증 필수 반영**: 리셋 정책 모호성 해소(실패=유지) / 429 백오프 필수(폭주) / 임계값 env(손절 공백 사용자 수용) / 스캐너 구조상 unknownCount 저장불가 → 명시 제외 / READ-ONLY 지표(진입 블록 아님, cid가 중복 방어).

**패리티 영향**: backtest 0(unknown=라이브 전용). 단, "메인넷 Binance도 unknown 누적인가, testnet처럼 pre-check만인가" → **§3 결정 필요**.

## 4. 이번에 '구현 안 함 / 거절' 권고 항목 (정직)

- **P1-5 라이브 지정가 본구현 — 연기**: 펜딩 주문 상태머신·백테스트 타임아웃 모델이 전무하여 backtest≡live 패리티가 깨진다. 백테스트는 '닿으면 즉시 체결', 라이브는 '타임아웃→마켓 슬리피지' → 전략이 백테스트 가정으로 과적합. DSR/PSR 재검증이 고위험 델타. §3 Q1~Q7 + 패리티 옵션 확정 전엔 코딩 진입 금지. KR은 어차피 getOrderByClientId 부재로 fail-closed 거절.

- **P1-10 KR reconcile 본구현 — 보류(API 미확정)**: KIS 미체결 조회 tr_id / 키움 api-id가 공식 문서·코드 어디에도 확정 기재되어 있지 않다(TTTC8434R/kt00018은 잔고일 뿐). 미확정 상태로 구현하면 조회 실패→reconcile 불가→fail-closed 동결 순환. 이번엔 **타입가드 역전 교정 + 메서드 스텁 + 테스트 강화**만(차단 안 됨), 실제 조회/취소는 API 확정 후.

- **P1-23 심볼맵 reconcile(방침 A) — 거절(이번)**: ~4주 고밀도 작업 + 계좌 다중봇 ambiguous(같은 심볼 복수 봇 귀속) 미해결. 라이브 명시 거절(방침 B)로 안전을 확보하고, 부분체결 발산 버그만 즉시 수정. reconcileSymbolMap/심볼별 reconMisses는 후속.

- **P1-22 KIS getCandles 구현 — 안 함(의도된 fail-closed)**: KIS 캔들 API 미연동 상태. 구현 대신 `throw`로 명시(조용한 빈배열 hold = 정직성 위반 제거). KIS E2E(P0-4) 완료 후 구현이 합리적.

- **P1-2 스캐너 unknown reconcile — 안 함**: 스캐너는 position_state가 Map<symbol> 구조라 unknownCount 저장 위치가 없다. 명시 제외(단일봇 전용)로 처리, 스캐너는 경고 로그만.
